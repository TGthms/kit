# Kit inventory and backlog

This file is the active implementation record. Current source is under `src/`, `messages/`, `content/`, `public/`, and `scripts/`. Do not use the disposable `out/` directory as source evidence.

## Current baseline (2026-08-29)

- **94 tools** in `src/lib/tools/registry.ts`.
- Next.js 16 App Router with static export, PWA shell, Cloudflare Pages (canonical) and GitHub Pages CI. GitHub Actions runs typecheck, lint, and tests before the Pages backup publish.
- Cloudflare Pages Free allows 20,000 files per deploy. Next 16 writes extra `__next.*.txt` segment-prefetch files per route (~23k files for 31 locale URLs). `scripts/prune-export.mjs` runs as `postbuild` and deletes those extras, keeping `index.html` and `index.txt` so client navigations still work. Cloudflare clones GitHub and runs `npm run build`; it does not upload the gitignored local `out/` folder.
- 30 first-class locales plus the legacy `/zh/` path alias; localized tool metadata, sitemap, robots, 62 legal documents, and a How Kit works story page at `/{locale}/how/` (honest tables for what crosses the network, what Kit downloads once, the home greeting system, and offline; locale-aware links, never a hardcoded `/en/` path). No fake 0%/100% bars. Legal `/privacy/` stays the policy.
- `/` is an entry point, not a page: it picks a language from the stored choice or the browser and replaces to `/{locale}/`. It therefore names `/{defaultLocale}/` as its canonical, carries no `hreflang` list of its own, and is left out of the sitemap. Listing it would put a forwarding address in front of a search engine as though it were a destination, competing with the home page it forwards to. The document defaults in `src/app/layout.tsx` deliberately set no canonical and no language list, so a page that never states its own — the not-found document in particular — cannot claim the home page as itself. `<noscript>` on `/` is a list of every language, so a visitor without scripting can still choose one.
- `sitemap.xml` states `lastmod` from the commit (`src/lib/seo/build-date.ts`), not the build clock: a rebuild that changes nothing must repeat the same date, or a search engine stops treating the value as meaningful. `scripts/sitemap-split.mjs` then divides the single file Next writes into one per language and writes an index over them, so Search Console reports coverage for each language separately instead of one averaged number. The script checks the total before writing anything, so a mistake leaves the single-file sitemap in place rather than publishing a broken one.
- Pure engines and tests under `src/lib/`; client tool views under `src/components/tools/`; favorites and metadata-only history in Zustand stores.
- Canonical production site: `https://trykit.pages.dev`; GitHub Pages backup: `https://TGthms.github.io/kit/`.
- PWA shell cache is `kit-shell-v13`; Flight payloads live in `kit-rsc-v13` so a `.txt` body can never paint as the page. The worker never returns a redirect `Response` or a `fetch()` result with `redirected: true` (Safari: “Response served by service worker has redirections”). Document navigations to `.txt` fetch the HTML route instead. Cached HTML for the exact URL is returned immediately; a hung first-time navigate fetch falls back at 400ms (exact cache) / 8s (last-home). In-app clicks use cached `index.txt` so they stay in the tab after idle instead of becoming a full document load. After first paint the worker silently fills JS/CSS, chrome HTML and RSC for every locale, and all tools plus pdf.js/FFmpeg for the locale in use. Fills use low-priority fetches, pause on pointer/key/wheel, and pause again when the tab becomes visible. On Save-Data or a slow (2G) connection the worker prefetches only the language in use, skipping the other languages and the FFmpeg engine. Offline in-app clicks load cached HTML documents. This is full offline for the language you have open, not a 30-locale download of every tool on first visit.
- The Offline access page reports what the device actually holds, counted from the cache keys rather than by probing several thousand addresses: per language (complete or partway), per tool (reachable in every complete language), and for the media engines. Each language and tool can be removed on its own, or everything at once. Removing the app's own scripts, styles and icons is deliberately not offered — those are the application rather than something chosen on that page, and dropping them would leave the app unable to open its own pages. A language counts only languages the page can offer: addresses kept so an old link still resolves — a renamed tool, or `/zh/` — are prefetched but never counted, because nothing on the page can select them and counting them would leave every language permanently short of complete. `scripts/sw-precache.mjs` works both out from the export itself (the page asks not to be indexed; a language's home page names a different language as its own address) rather than from a second list to keep in step. Removal reaches them too, so removing everything leaves nothing behind.
- A download the visitor asked for fetches several resources at once (`OFFLINE_CONCURRENCY`), because they are waiting on the page and watching the bar. The optional background fill stays strictly one at a time, so it never competes for bandwidth with what someone is looking at.
- What was downloaded is recorded on the device (`kit-offline-plan` in localStorage, alongside the release it was fetched for), not inside the cache — a new release replaces the cache and would take the record with it, which is exactly when it becomes useful. When the record names an older release, or the cache has rolled past it, the page says so and re-runs the same selection in one tap. Nothing downloads without a tap. Removing everything forgets the record, so a visitor who declined the content is not asked for it again.
- After a deploy, a tab that still names deleted hashed chunks reloads once (`ChunkLoadError` / failed dynamic import). Retry on the error screen does the same. A 10s guard stops a reload loop.
- Locale documents bake `lang` and `dir` on `<html>` (`/ar/` is `lang="ar" dir="rtl"`). `/` stays an English LocaleGate. The boot locale-lang script remains a backup (`zh` → `zh-Hans`).

## Completed correctness and product work

- FFmpeg trim and GIF clipping use explicit `start` + `duration` semantics and re-encode instead of relying on container stream-copy timing.
- MP4/MOV/MKV conversion uses explicit H.264/AAC transcoding; silent-video speed processing has a video-only fallback.
- History summaries and options are sanitized so filenames, watermark text, ranges, and arbitrary free-form values are not persisted.
- PDF watermark, page-number, and signature rendering can use browser Unicode text rendering for non-Latin input.
- Media waveform decoding skips files over 100 MB to avoid freezing the tab.
- Image download extensions are derived from the resulting Blob MIME type.
- PDF organize supports drag-and-drop page reordering.
- PDF.js documents are explicitly destroyed after normal processing. Raster and text extract cap at the first 200 pages and warn when a file is longer.
- Privacy Policy and Terms exist for all 31 path locales; legal-loading tests cover every first-class locale.
- SQL comments and non-identifier JSON keys are preserved; invalid HTML entity code points no longer crash decoding.
- Everyday category includes unit conversion, currency, text counting, time zones, meeting overlap, dates, tips/splits, percentage, loan/compound interest, BMI and calorie estimates, stopwatch/countdown, and random generation. Images-to-PDF lives under PDF export.
- PDF page numbers, PDF-to-images ZIP, images-to-PDF, form flattening, PDF metadata, PDF lock/unlock, image EXIF inspection, rotate/flip, filters, favicon export, XML/JSON, SQL, regex, hashing, UUID, color, Lorem ipsum, QR, and password tools are registered and implemented.
- PDF merge thumbnails are rendered concurrently, while PDF-to-image processing still cleans up PDF.js documents.
- Images-to-PDF defaults to A4 fit-to-page with margins; the tool can switch to original image size. The engine keeps both modes.
- The everyday world-clock city list is maintained in `src/lib/converter/cities.ts` and uses IANA time zones through `Intl`. Card and converter labels are localized (`tools.timezone-converter.city*` / `zone*`); English fallback names stay on the city objects. Hong Kong is labeled with China in every catalog.
- The static app includes an explicit CSP meta policy for same-origin assets plus Frankfurter. pdf.js and FFmpeg WASM are vendored under `public/vendor/` (synced on postinstall/prebuild). FFmpeg’s core WASM is shipped gzipped (`ffmpeg-core.wasm.gz`, ~10 MiB) because Cloudflare Pages rejects files over 25 MiB; the browser gunzips it before load. `@ffmpeg/core` is GPL-2.0-or-later (H.264 / LAME); Kit source stays MIT, and README / Terms / Privacy disclose the engine. Kit-owned boot scripts live in `public/boot/`. `'unsafe-inline'` remains because Next.js static export emits inline Flight payloads. Cloudflare `_headers` also sends CSP with `frame-ancestors 'none'`.
- Mobile tool headers collapse after scrolling to a compact iOS-like back affordance (fixed overlay, not sticky); tool title, description, client-side note, and favorite action stay in the page and scroll under it.
- Keyboard shortcuts avoid Cmd/Ctrl bindings that collide with macOS, Windows, and browser commands: `/` focuses search, `R` runs the active tool, `?` opens help, and `Esc` closes help. Cmd/Ctrl+Enter remains available as an optional form-style run gesture.
- Theme persists in localStorage (`theme` = applied value, `kit-theme-context` = user intent). System is the default until the user taps Light or Dark. Settings appearance is Light and Dark only (no Match system control); the auto-follow policy still runs. A header or Settings Light/Dark tap always paints that appearance immediately and keeps it for this visit, even when auto policy would force Dark. Auto policy still applies on boot (and on OS / 22:00 / 05:00 when the user has not tapped this visit): follow System by default; keep Dark; if the stored intent is Light while the OS is dark or it is night (22:00–04:59), force Dark (the Light intent is restored when that condition lifts). Light/dark switches use a circular View Transition wipe from the control (instant when View Transitions are missing or reduced motion is on).
- Countdown, stopwatch, world-clock faces, and live numeric results use Scritto (`@scritto/react`). The clock is one formatted `HH:MM:SS` string (colons stay; only changed glyphs roll). Running countdown uses `trend={-1}`; running stopwatch and world-clock ticks use `trend={+1}`; idle reads direction from the value. Centiseconds stay static so sub-second ticks do not stack ghosts. World-clock cards update once a second, inside Scritto’s duration window.
- Copy actions confirm on the button (icon + “Copied”); they no longer toast on success.
- Home Start here lists tools only (Currency first, BMI & calorie last). Everyday converters and Everyday tools are category pages, not featured cards.
- Text counter reading time is ~220 WPM for alphabetic text and ~400 characters/min for CJK, shown as `45s` / `1m 15s` rather than rounded-up minutes.
- Form fields use 16px type so iOS Safari does not zoom into converter search inputs on focus. The installed PWA also locks page pinch-zoom (`maximum-scale=1`) while still following iOS Dynamic Type via `-apple-system-body` (rem layout scales with Settings → Display & Text Size). That keyword is gated to iOS (`-webkit-touch-callout`); desktop Safari maps it to 13px macOS body and would shrink the rem layout. Browser tabs stay pinch-zoomable.
- Mobile PWA tab bar is a floating glass capsule just above the home indicator (content scrolls underneath), lifted 2px off the indicator. The capsule uses a thinner fill and a stronger blur than other chrome so the material reads as iOS ultra-thin glass. The selected-tab highlight is a concentric `rounded-full` stadium that matches the bar’s circular ends. Switching tabs springs the gliding pill (slight overshoot) and pops the selected icon; reduced motion skips both. Re-tapping the current tab scrolls to the top. The highlight follows the page that is actually on screen: a tap moves it at once so the bar answers immediately, and the route change that fulfils the tap spends that, so going back afterwards lands the highlight on the tab you returned to rather than the one you left. The bar slides away while the virtual keyboard covers the bottom. Compact tool headers on mobile are a fixed glass overlay (not sticky, not in document flow); only the back control takes taps, so scrolling stays smooth. 2-item segments (timer mode, appearance) still use a gliding pill; switches use a short overshoot on the thumb. The document scroller keeps native rubber-band bounce at the top and bottom; overscroll is not locked in the installed PWA.
- Cover content is a drawable visual overlay (not true redaction). Shrink-as-images rasterizes pages to JPEG and says so in the tool name and limits.
- World clock public URL is `/tools/world-clock/`; `/tools/timezone-converter/` still loads the same tool and rewrites the path.
- Images → PDF defaults to A4 fit with an original-size option. JPEG EXIF orientation is applied via canvas decode.
- pdf.js CMaps, standard fonts, WASM, and ICC profiles are vendored next to the worker (`scripts/sync-vendor.mjs`).
- Home sub-greetings can carry in-app links (`<tool>` / `<page>` rich tags). World Password Day and Encryption Day wrap a phrase to the password generator; Data Privacy / Safer Internet / Computer Security days and some kit facts append a Learn more link to `/{locale}/how/`. Morning filler lines stay plain.
- Home greetings pair the subtitle with the main line (Kit/privacy → Kit-knowledge facts; productivity → workflow facts; time-of-day → general facts plus period flavor). Monday morning and Friday afternoon/evening/night add extra main lines; weekends add a third weekend line. Observances still win the calendar day. Current holidays keep three distinct subtitles each; Good Friday’s subtitle is always John 19:30 from the World English Bible (public domain, stored in `src/lib/home/verses.ts`, never translated, hidden with other Christian days for `ar` / `he` / `hi`). Six further tech/internet days: Data Privacy Day (28 Jan), World Emoji Day (17 Jul), Software Freedom Day (3rd Saturday of September), Global Encryption Day (21 Oct), International Internet Day (29 Oct), World Digital Preservation Day (first Thursday of November). The sub-greeting uses opacity-only CSS (`fade` / slower `fadeSlow` for evening, night, and solemn days) at the same time as the main line; reduced motion shows both lines immediately. Greeting / How Kit works / home chrome copy is native in every catalog (not English calques). English greetings are American English, not translations of the Chinese lines. Korean Gregorian New Year is 신정, not 설날; Vietnamese is Tết Dương lịch. `/zh/` stays an alias of `zh-Hans`.
- Hidden greeting preview, production included: `/{locale}/?date=YYYY-MM-DD` uses that calendar day at the current clock hour (`greetingDate` still works). Optional `time=HH:MM` or `time=HH:MM:SS` (alias `greetingTime`) pins the clock; the preview then advances so a New Year flip can be watched. `date=2026-12-25T23:59:03` is also accepted. Optional `greetingSeed=integer` pins the pair. Invalid values are ignored. `/` keeps the query when it hops to `/{locale}/`. Category URLs still show the greeting when a preview query is present (the New Year card always did). Examples: `/en/?date=2026-12-25`, `/en/?date=2026-12-31&time=23:59:03`, `/zh-Hans/?date=2026-03-14&greetingSeed=3`. Good Friday 2026 is `2026-04-03`. New Year’s Eve is only the last 10 local minutes of 31 Dec — `?date=2026-12-31` in the afternoon is the ordinary 31 Dec greeting, not the countdown.
- New Year card (local Gregorian midnight): appears 10 minutes before 1 Jan, counts down with Scritto `MM:SS`, then shows “Happy New Year!” for the rest of 1 Jan. The card ticks the clock locally so home does not re-render 4×/s; a live `celebrate` is not overwritten by the frozen parent countdown snapshot. A tab left open on 31 Dec wakes at 23:50; greeting period changes on 1 Jan still run under the card. On the home grid the card is the `h1` and the time-of-day line is `h2`; on category pages the card is not a heading (PageHeader stays the `h1`). The page greeting does not also use `greeting.observance.newYear`. Countdown subtitle and clock `aria-label` follow remaining time. Full-screen `fireworks-js` `start()` runs for the remainder of the first 10 seconds after the flip (or if the tab opens in that window). Opening home later on 1 Jan fires one `launch()` volley (not if this visit already had the 10s show). Tab hide uses `pause()`, not `stop()`. Reduced motion skips fireworks and digit rolls.
- Tool routes omit `home.greeting` / `subtitleFacts` / `subtitleObservance` / `newYearCard` from the client message payload. Home still ships those strings.

## Remaining backlog

### Product / UX

- True content-stream redaction; current cover is visual-only and is disclosed as such.
- OCR for scanned PDFs; deferred because a client-side OCR engine would add a large download.
- More codec-specific validation and clearer unsupported-format errors for FFmpeg WASM.

### Engineering

- **`scripts/i18n/values/*.txt` are stale and `scripts/i18n/emit.py` cannot run against them.** The packs hold 587 lines while `messages/en.json` has more than 1,700 leaf keys, and their key order no longer matches English, so `emit.py` stops with a pack mismatch. `messages/*.json` are the working source of truth and were updated directly with `scripts/i18n/upsert_keys.py`, which sets nested keys without reshuffling the surrounding order. Reconciling the packs means regenerating each one in English leaf order from the catalogs — while doing that, re-read the whole set, because the packs are the only place the intended translation of a given key is recorded.
- `messages/zh.json` is unused: the `/zh/` path alias resolves to the `zh-Hans` catalog through `messageFileFor`, and nothing reads the file. It also carries English text for part of the `settings.offline*` block, unlike every other catalog. Keeping it in step with `zh-Hans` would need the packs above to work first.
- Add focused React tests for the remaining high-risk tool flows and accessibility behavior.
- Replace hard-coded file-tool classification with an explicit registry property.
- Hash-based `script-src` (dropping `'unsafe-inline'`) is blocked by Next.js Flight inline scripts on static export.
- **ESLint 10 is blocked upstream, so the deprecation warning on `eslint@9.39.5` is expected.** Every plugin `eslint-config-next` pulls in caps at ESLint 9 (`eslint-plugin-react` at `^9.7`, `typescript-eslint` at `^9`, `eslint-plugin-import`/`-jsx-a11y`/`-react-hooks` at `^9`), and 9.39.5 is the last 9.x. Upgrading to 10 crashes the linter with `getFilename is not a function`, which would fail the lint gate. Retry once `eslint-config-next` moves its plugins to ESLint 10.
- **Dependency install scripts are denied on purpose** (`allowScripts` in `package.json`): `@parcel/watcher`, `@swc/core`, `unrs-resolver` and `fsevents` all ship prebuilt binaries as optional dependencies — 12, 12, 21 and a macOS-only binding respectively — so their scripts are unreachable source-build fallbacks. Denying them keeps install-time code execution off and stops `npm ci` needing a C++ toolchain. Approving one would only matter if a future platform lost its prebuilt binary; `npm approve-scripts <pkg>` is the way back if that ever happens.

### Discovery (after SEO deploy)

Google’s site name for `trykit.pages.dev` used to fall back to Cloudflare because `/` had no `WebSite` JSON-LD. After the sitename deploy:

1. Search Console → URL Inspection on `https://trykit.pages.dev/` → Request indexing.
2. Confirm the sitemap `https://trykit.pages.dev/sitemap.xml` is submitted. It is now an index over one file per language; submit the index and let Search Console follow the children, then check each child’s reported URL count. If a fetch still fails, the response is verifiably correct from outside (200, `application/xml`, valid XML, no dead addresses), so look next at Cloudflare for a bot rule catching the crawler before the site sees it.
3. In the coverage report, the two reasons Kit was showing — “Duplicate, Google chose different canonical than user” and “Page with redirect” — both traced to `/` serving a page while forwarding to a language and claiming itself canonical. After the change, expect `/` to sit under “Alternate page with proper canonical tag” and the language pages to consolidate under `/{locale}/`. Use “Validate fix” once the index has been re-fetched.
4. Wait days to weeks. Prefer “Kit”; acceptable fallback is `trykit.pages.dev`, not Cloudflare.
5. Custom domain (highest leverage, Tim): Cloudflare Pages → Custom domains, then change `SITE_URL` and 301 `trykit.pages.dev`. Do not mix hosts before that.
6. GitHub repo: description “Everyday browser tools that stay on your device”, topics (`pdf`, `privacy`, `pwa`, `offline`, `nextjs`), social preview `/og/kit.png`.
7. One honest listing each, not spam: PrivacyGuides / privacytools.io, AlternativeTo, Awesome Privacy. Optional Show HN or Product Hunt on a launch day.
8. Bing Webmaster Tools + the same sitemap (no analytics on Kit).
